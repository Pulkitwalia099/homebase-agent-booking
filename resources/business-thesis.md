# Homebase business thesis

Working hypothesis · 2026-10-05

**Homebase makes local services bookable by personal agents.** An agent describes the job once; Homebase returns suitable offers from participating businesses and carries the chosen one through to a verified booking. Homebase handles supplier enrollment, software connections and exceptions across agents.

## The promise to test

For an eligible standard clean with all required customer details and a genuinely bookable slot:

| Outcome | Illustrative current path | Homebase target |
| --- | ---: | ---: |
| Customer request to confirmed booking | 15 minutes | 1 minute or less |
| Agent token cost per completed booking | 100 indexed units | 10 or fewer indexed units |
| Selection | Options assembled from separate searches | A relevant shortlist with verified service fit, price and availability |

These are **targets, not measured results**. The headline is **10×+ faster, 10×+ lower agent token cost, and better selection**. Measure time from request to confirmed booking and agent token cost per completed booking, including retries and customer dialogue. Track external API and human support cost separately. Better selection requires enough suitable, bookable suppliers.

## Why this could work

Today an agent may combine Google results, ratings, websites, booking forms, calls and emails, then reconcile different services, prices and slots. Some cleaners already offer online booking and some agents can call or pay. The hypothesis concerns the *whole path across fragmented suppliers*, through an accepted booking.

Homebase would standardize each willing cleaner's service area, scope, prices and capacity; connect to its existing booking software; and return confirmed or pending status accurately. The cleaner's system stays authoritative. Each cleaner must opt in; connecting its software vendor alone does not grant access to its inventory.

## Who pays, and why not go direct?

The consumer gets a suitable, reliable choice. The agent company keeps the consumer relationship and uses Homebase only if its coverage, completion rate and total cost beat direct integrations. The cleaner opts in for profitable new customers. Its software vendor keeps its existing relationship.

Test one cleaner-funded fee after a **new-to-provider customer completes and pays for the first clean**, shared with the agent company. The agent earns for demand; Homebase earns for usable supply and execution. Homebase's share must cover onboarding and support. Wajo or another agent can go direct, so Homebase must demonstrate supplier access and operating work worth paying for. A flat transaction fee belongs to a different, execution-only offer.

## First proof, then scale

Try standard residential cleaning in a bounded Boston-area market **only if** an agent has relevant requests and willing cleaners have capacity there. Talk to both sides before choosing an integration. With one agent and one or two cleaners, compare actual time, token cost, offer quality, fulfillment, human intervention and contribution against the agent's existing process. Include unsuccessful requests. Ask both sides to continue at agreed economics.

Pursue the company if repeated demand, reliable bookings and positive unit economics make the shared supplier network preferable to each agent building directly. Otherwise it may be a feature or service business. A venture-scale case requires multiple demand partners and repeatable supplier onboarding.

**Visual story:** lead with one request and the proposed 15-minute/100-unit → 1-minute/10-unit outcome. Then compare today's fragmented path with Homebase's single route. Place the supplier stack below: cleaning company → booking software → optional front office → Homebase → consumer agents.
